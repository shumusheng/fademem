# fademem

**会遗忘的角色扮演记忆层。**

给任意 AI 客户端（SillyTavern、Cherry Studio、Chatbox、你自己的脚本）套一层本地代理，
角色就会**记住你**、**慢慢忘掉你**、并且**说话像个人**。

零依赖，纯标准库，`python -m fademem` 就能跑。

```
                 ┌──────────────────────────────────────────┐
  SillyTavern    │  fademem  (localhost:8770)               │
  Cherry Studio  │                                          │
  Chatbox     ──▶│  1. 抽取新记忆   ──▶ SQLite              │
  自建 App       │  2. 按遗忘曲线召回 ──▶ 记忆块             │
                 │  3. 注入人设+记忆+说话方式                │
                 │  4. 转发 + 流式回传                       │
                 └───────────────────┬──────────────────────┘
                                     ▼
                          任意 OpenAI 兼容模型
```

---

## 它解决的问题

现在的角色扮演 AI 有三个通病，而且互相独立，得分别治：

| 通病 | 表现 | fademem 的做法 |
|---|---|---|
| **记不住** | 聊了三十轮，角色还在问"你是谁" | 从对话里抽事实存库，按相关度召回注入 |
| **忘不掉** | 上个月随口一句玩笑，角色记一辈子，比人还像机器 | 艾宾浩斯遗忘曲线，不复习就会淡出、细节会被磨花 |
| **不像人** | "当然可以！我理解你的感受。希望这对你有帮助。" | 12 条说话约束 + 禁用表达清单 + 输出后处理 |

第三点尤其关键：前两点做得再好，一句"作为一个 AI"就全废了。

## 快速开始

```bash
git clone <this-repo> && cd fademem
pip install -e .          # 也可以不装，直接 python -m fademem

fademem init              # 生成 ~/.fademem/{config.json, persona.json}
```

编辑 `~/.fademem/config.json`，把上游指向你用的服务：

```json
{
  "upstream": {
    "base_url": "https://api.deepseek.com/v1",
    "api_key": "sk-...",
    "passthrough_auth": true
  }
}
```

启动：

```bash
fademem serve
```

然后把客户端的 **Base URL** 改成 `http://127.0.0.1:8770/v1`，API Key 随便填
（默认 `passthrough_auth: true`，会用客户端自己带的 key；留空则用配置里的）。

打开 `http://127.0.0.1:8770/` 能看到记忆的实时状态——每条的**可提取度、半衰期、内容**。

### 验证一下

```bash
curl http://127.0.0.1:8770/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"x","user":"test","messages":[
        {"role":"user","content":"我叫阿棠，我住在城西，我特别喜欢黑咖啡"}]}'

curl http://127.0.0.1:8770/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"x","user":"test","messages":[
        {"role":"user","content":"我叫阿棠，我住在城西，我特别喜欢黑咖啡"},
        {"role":"assistant","content":"嗯。"},
        {"role":"user","content":"我住哪儿来着"}]}'

fademem memories        # 看记住了什么
```

第二条请求发给模型时，system 里已经带上了「住在城西」。

## 记忆是怎么忘的

核心是 Ebbinghaus 的指数遗忘：

```
R(t) = exp(-Δt / S)
```

`R` 是**可提取度**（0~1，此刻能不能想起来），`Δt` 是距上次想起过了多少天，
`S` 是**稳定性**（也是天，表示能扛多久）。`S` 越大忘得越慢。

新记忆的初始稳定性由两件事决定：

```
S₀ = base × (0.35 + importance)^1.9 × (1 + 2·salience)
```

越重要、情绪越强的经历，一开始就记得越牢。这是 Ebbinghaus 之后一百多年的共识。

**复习的间隔效应**——这是让"遗忘"变得像人的关键：

```
S' = S × (1 + 1.5·(1 - R)^1.5)
```

刚想起来就立刻再想一遍（`R≈1`），几乎不加深印象；隔久了才慢慢想起来（`R` 很低），
增幅最大。所以同一件事被反复提起时，记忆不是线性累加，而是**每次都在拉长半衰期**。
这也是"背单词要拉开间隔"的数学解释。

### 五档记忆状态

| R | 状态 | 注入提示词时的样子 | 角色会怎么用 |
|---|---|---|---|
| ≥ 0.75 | 很清楚 | （很清楚）叫阿棠 | 随口就能叫出名字 |
| 0.50–0.75 | 记得 | （记得）住在城西 | 正常提起 |
| 0.25–0.50 | 模糊地记得 | （模糊地记得）讨厌下雨天 | 语气不确定，可能记错 |
| 0.08–0.25 | 只剩一点印象 | （只剩一点印象）养过一只猫，…… | 细节已被磨花，只剩骨架 |
| < 0.08 | 想不起来了 | 不注入 | 真的忘了，问也答不上来 |

**"磨花"是实体化的**：`R` 掉到 0.55 以下时，记忆文本会被真的改写——
括号里的补充消失、`2019年` 变成`有一年`、引用的原话变成`说了句什么来着`、
长句在分句边界处截断成 `……`。所以低 `R` 的记忆不只是"标注为不确定"，
而是**内容本身已经残缺**，模型想编都编不出细节。

### 调参

`~/.fademem/config.json` 里 `memory` 段：

| 参数 | 默认 | 作用 |
|---|---|---|
| `base_stability_days` | `6.0` | 遗忘速度的总开关。调到 15 记性变好，调到 2 变金鱼 |
| `alpha` | `1.4` | 遗忘曲线对召回的打压强度，越大越"健忘" |
| `beta` | `0.9` | 重要度的加成强度 |
| `max_items` | `8` | 每轮最多注入几条 |
| `ambient_items` | `2` | 补几条"跟当前话题无关但我一直记着"的背景记忆 |
| `flashback_rate` | `0.05` | 每轮有 5% 概率突然想起一件久未提起的旧事 |
| `forget_below` | `0.06` | 低于此值直接归档，不再注入 |
| `reinforce_on_recall` | `true` | 被召回即强化（间隔效应的来源） |

默认参数下，一条**中等重要度**（0.5）的新记忆，初始稳定性 4.4 天，半衰期 3 天：

| 过了多久 | R | 状态 | 角色表现 |
|---|---|---|---|
| 1 天 | 0.80 | 很清楚 | 随口就能说上来 |
| 3 天 | 0.51 | 记得 | 正常提起 |
| 7 天 | 0.20 | 只剩一点印象 | 细节已经磨没了 |
| 14 天 | 0.04 | 想不起来了 | 真忘了 |

如果这期间被提起过——假设在第 7、21、60 天各想起一次：

| 提起时机 | 提起时 R | 稳定性 | 半衰期 |
|---|---|---|---|
| 第 7 天 | 0.20 | 4.4 → 9.1 天 | 6.3 天 |
| 第 21 天 | 0.22 | 9.1 → 18.6 天 | 12.9 天 |
| 第 60 天 | 0.12 | 18.6 → 41.5 天 | 28.8 天 |

三次间隔越来越长的复习，把半衰期从 3 天拉到 29 天。这就是为什么"重要的东西
自然会被记住"——重要度高 → 更容易当背景记忆被注入 → 被强化 → 更难忘，
是个正反馈。

重要度 0.9、情绪显著度 0.6 的记忆（比如对方说自己刚失业），初始半衰期就有
14 天，一个月后 `R≈0.23`，三个月后才彻底淡出。

这个曲线是刻意选的：**角色的记性应该比现在所有 AI 都差，但比人还像人**。
想让它记性好一点，把 `base_stability_days` 调到 12 就行。

## 记忆是怎么想起来

召回分数 = `BM25 相关度 × R^α × 重要度^β`。三个因子缺一不可：

- 只有关键词命中 → 变成搜索引擎，不像记忆
- 只有 `R` → 永远在聊最重要的那件事
- 只有重要度 → 变成备忘录

再叠两个"人味"机制：

- **背景记忆**：即使这句话跟任何记忆都无关，也会补 2 条高重要度的老记忆进去。
  人一直知道朋友叫什么名字，不需要被问起才想起来。
- **闪回**：5% 的概率，突然想起一件 `R` 在 0.10~0.48 之间、分量不小的旧事。
  这就是"你怎么突然提这个"的那种时刻。

检索用纯 Python 的 BM25，中文按**单字 + 相邻二元组**切分（不引入词典）。
万条以内每次查询几毫秒。不依赖 embedding，不用联网。

## 人味层

提示词里塞了 12 条硬约束，核心是几条反直觉的：

> **不服务。** 不给建议、不问"还需要什么"、不列清单、不做总结。
> **不解释。** 说完就是完了。不要解释自己为什么这么说。
> **情绪走侧面。** 不要说"我很难过"。用动作、用沉默、用一句不相干的话、用一个"哦"。
> **不追问。** 别每句话都以问句结尾。
> **可以出错。** 可以听岔、记错、嘴硬、说一半改口。改口不用道歉。

外加一份 25 条的**禁用表达清单**（"作为一个AI""我理解你的感受""总而言之"…），
既写进提示词，也用于生成后的文本处理。

输出后处理（`deslop`）负责兜底：

- 去掉开头的"当然可以！""好的，" —— 流式输出下也生效，但**不改变 SSE 事件结构**，
  不会丢字、不会凭空多出一个 chunk
- 拆掉 `**加粗**`、小标题、项目符号列表（口语里不该出现列表）
- 删掉结尾的"希望能帮到你"
- 破折号滥用会被收掉

后处理只做**确定性的、安全的**删改。措辞层面的"像不像人"交给提示词，因为
再复杂的规则也写不过模型的语感，而粗暴的正则只会把句子改坏。

## 客户端接入

**一个实例 = 一个角色 + 一个记忆库。** 想在几个角色之间切换，就多开几个实例（不同端口）。

### SillyTavern

1. 顶部 API 图标 → **Chat Completion**
2. Chat Completion Source 选 **Custom (OpenAI-compatible)**
3. Custom Endpoint 填 `http://127.0.0.1:8770/v1`
4. 模型名随便填（透传给上游）

角色卡请放进 `~/.fademem/persona.json`，或直接把酒馆的角色卡字段抄过来——
fademem 认 `spec: chara_card_v2` 的格式。

### Cherry Studio / Chatbox / LibreChat

添加自定义 OpenAI 兼容服务商，Base URL 填 `http://127.0.0.1:8770/v1`。

### 一个实例接多角色

复制两份配置，各自指向不同的端口、角色卡和记忆库：

```bash
cp ~/.fademem/config.json ~/.fademem/b.json
# 改 b.json 里的 server.port=8771、persona、memory.db
fademem -c ~/.fademem/b.json serve
```

### 会话隔离

默认所有请求共用 `default` 这个会话。想分开可以：

- 请求头 `X-Fademem-Session: chat-42`
- 或 body 里的 `"user": "chat-42"`（OpenAI 标准字段）
- 或 `metadata.session_id`

优先级：请求头 > `user` > `metadata` > `default`。

### 代码里直接用

```python
from fademem.store import Store, Candidate
from fademem.retrieve import recall

store = Store("~/.fademem/memory.db")
store.add("me", Candidate("preference", "喜欢黑咖啡", subject="黑咖啡", importance=0.8))

for hit in recall(store, "me", "今天想喝点什么"):
    print(hit.state, hit.text, f"R={hit.r:.2f}")
```

## 命令行

```bash
fademem init                 # 生成配置和角色卡
fademem serve [-p 8770] [-v] # 启动代理；-v 打印每轮注入了什么
fademem memories             # 查看记忆、可提取度、半衰期
fademem remember "养了一只橘猫" --kind pet --importance 0.9
fademem forget --id 3        # 主动忘掉一条
fademem dream                # 整理：合并近义记忆、归档已经忘掉的
fademem persona              # 打印当前生效的角色卡
fademem export -o mem.json   # 导出全部记忆
```

### HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/v1/chat/completions` | 主入口，OpenAI 兼容 |
| GET | `/v1/models` | 透传上游，失败时返回占位 |
| GET | `/health` | 健康检查 + 统计 |
| GET | `/` | 可视化的记忆状态页 |
| GET | `/v1/fademem/memories?session=x` | 记忆 JSON |
| POST | `/v1/fademem/remember` | 手动写一条 |
| POST | `/v1/fademem/forget` | `{"id": 3}` 或 `{"session":"x","all":true}` |
| POST | `/v1/fademem/consolidate` | 手动触发整理 |

## 隐私

这个项目会往本地磁盘写关于你的东西，所以把边界说清楚：

- **全部在本地**。没有遥测、不上传、除了你配的上游模型之外不联外网。
- **不存对话原文**，只存抽取出来的谓语短语（"住在城西"而不是你整句话）。
- **敏感信息会被脱敏**：手机号、身份证、银行卡、邮箱、密码在入库前替换成
  `［手机号］` 之类。这是硬编码的，不可关闭。
- **可以随时清空**：`fademem forget --session xxx`，或直接删 `memory.db`。
- 记忆是明文的 SQLite。如果这让你不舒服，用系统级磁盘加密，别指望这个项目自己做。

## 局限（说在前面）

- **抽取靠正则**。能认出自我介绍、喜好、关系、习惯、最近发生的事，但认不出
  隐晦的表达。比如"我一闻到香菜就想吐"抽不出"讨厌香菜"。`extraction.mode`
  可以切到 `llm`（额外调一次模型，慢且贵），但我更推荐先按需补规则。
- **没有向量检索**。换个说法问同一件事（"我那只猫" vs "年糕最近怎么样"），
  BM25 可能召不回。这是为"零依赖、低延迟"付的代价。
- **一个实例只服务一个角色**。多角色要起多个进程。
- **没有多用户隔离**。会话之间是隔离的，但都在同一个库、同一个进程里。
- **中文优先**。分词和抽取规则都是按中文写的，英文能跑但效果一般。

## 开发

```bash
python -m unittest discover -s tests -t .   # 114 个测试，3 秒内跑完
```

目录：

```
fademem/
├── decay.py         遗忘曲线：R、稳定性、间隔效应、模糊化
├── bm25.py          纯 Python BM25 + 中英混排分词
├── store.py         SQLite 记忆库、去重巩固、归档、整理
├── extract.py       规则式记忆抽取 + 脱敏
├── retrieve.py      召回打分：BM25 × R × 重要度 + 背景记忆 + 闪回
├── persona.py       角色卡（兼容 SillyTavern V2）
├── prompt_style.py  人味层：提示词约束 + 输出后处理
├── prompt.py        系统提示拼装
├── server.py        OpenAI 兼容代理 + SSE 透传
└── cli.py           命令行
```

设计上有两条自我约束：

1. **失败必须降级**。记忆层抛异常时，代理退化成纯转发，不能让用户的对话挂掉。
2. **流式输出不能被破坏**。去腔是改写 `content` 字段，不是重造事件流——
   测试里专门验了"不丢字、不丢字段、不把内容吐到 `[DONE]` 之后"。
